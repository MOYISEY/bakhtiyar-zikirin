# Раунд 1 — код, корректность и безопасность System Atelier

Независимый аудит агентом Codex `v2_audit_code`, 1 октября 2026, 18:21–18:35 UTC. Проверены `index.html`, `src/main.ts`, `src/scene.ts`, `src/fallback.ts`, релевантные стили и публичные исходники двух проектов. Продуктовые файлы аудитор не изменял; исправления выполнил основной агент, после чего аудитор повторил проверки.

Итог: две найденные проблемы исправлены и перепроверены. Открытых блокирующих замечаний в проверенном коде нет. Это аудит исходников и локального Chromium; он не подменяет последующие дизайн-аудит и проверку опубликованной версии.

## Находки и исправления

### P2 — незавершённая очистка при отказе во время инициализации

Исходная версия защищала только `new WebGLRenderer`. Исключение при создании поверхности после успешного выделения WebGL приводило к 2D fallback через `main.ts`, но не вызывало очистку уже созданных ресурсов сцены.

Воспроизведение: до загрузки страницы `HTMLCanvasElement.getContext('2d')` заменён на возврат `null`, WebGL2 оставлен доступным. Инициализация остановилась на создании первой текстуры. Fallback работал, однако счётчик GPU-вызовов показывал созданный renderbuffer без удаления и неосвобождённый environment render target. Исходные результаты сохранены в [audit-1-code-before.json](audit-1-code-before.json).

Исправление: общий реестр владельца ресурсов `own/release`; защитный `try/catch` всей дальнейшей инициализации; остановка pending RAF, обработчиков и observers при ошибке. Геометрии, материалы, текстуры, PMREM/environment и renderer освобождаются при ошибке и при завершении страницы. Повторная инъекция отказа подтвердила удаление environment renderbuffer и дополнительного framebuffer/texture, скрытый canvas без `tabindex` и рабочие 2D режимы/слои. См. [audit-1-code-after.json](audit-1-code-after.json).

GPU ledger считает также внутренние объекты Three.js, поэтому здесь не заявляется нулевое число всех объектов GPU после `renderer.dispose()`. Проверены API очистки принадлежащих сцене ресурсов и работоспособность fallback.

### P2 — нестабильный сохранённый кадр при паузе

При `prefers-reduced-motion: reduce` повторные ранние снимки canvas изменялись, хотя `aria-pressed=true` и счётчик draw calls оставался неизменным. При визуальном просмотре одного повторного кадра модель отсутствовала. Состояние не было вращением сцены; постоянный цикл рендера при паузе отсутствовал. Результаты первоначальной проверки: [audit-1-lifecycle-before.json](audit-1-lifecycle-before.json).

Исправление: `preserveDrawingBuffer: true` сохраняет последний кадр без постоянного RAF. После исправления четыре снимка подряд совпали по SHA-256 (`0ec3b1c786627fdc55670165703662e249f1b4862cd7bab69ea35cada987af80`), модель видна при повторном визуальном просмотре; `drawElements` во время всех четырёх снимков оставался 155. См. [audit-1-lifecycle-after.json](audit-1-lifecycle-after.json). Влияние сохранения буфера на производительность должно учитываться в следующем аудите.

## Выполненные проверки

- `npx tsc --noEmit`: ошибок TypeScript нет.
- Chromium 153, viewport 1440×1000, reduced motion: три режима имеют разные изображения и корректный `aria-pressed`; три слоя меняют текст; стрелка вращает сцену, Home возвращает прежний кадр; ошибок JavaScript в базовом сценарии нет.
- Настоящий переход на локальный `favicon.svg` и браузерный `goBack`: наблюдался `pageshow.persisted=true`; после возврата режим `wire` работал. Использован `waitUntil: 'commit'`, чтобы не ожидать `DOMContentLoaded` у восстановленной страницы.
- Отдельная синтетическая ветка persisted lifecycle: draw calls 1112 до паузы и во время неё, 2984 после возобновления. Она проверяет обработчик, а не служит доказательством admission в bfcache; для admission выше использована настоящая навигация.
- `WEBGL_lose_context`: canvas скрывается, `tabindex` удаляется, 3D кнопки скрываются, 2D режим `wire` и слой `logic` продолжают работать.
- Reduced-motion «Проследить клик»: последовательность завершилась без удержания disabled-состояния и без оставшегося сигнального слоя. Статус описал завершение пути.
- No-JavaScript для собранного HTML `/docs/`: заголовок виден, подключена CSS, используется Onest, доступны три кейса и три нативных `details`; первый блок действительно открыт кликом. Canvas скрыт.
- Свежий viewport 320×720 и переход desktop→320: при визуальном просмотре модель помещалась в canvas. Ширина документа равнялась 320, ширина canvas — 288. Доказательств клиппирования камеры в этих состояниях не найдено; изменение камеры не требовалось.
- Статическая проверка security surface: внешние ссылки имеют `noopener noreferrer`; динамические тексты вставляются через `textContent`/`replaceChildren`; нет HTML-вставки пользовательских данных, формы отправки, токенов, личной почты, CV/PDF, сторонней аналитики или local-storage авторизации в продуктовых файлах.

Art Portal (`42cc312fc009323a108ea8e130f39e8e5ea4e9a6`) сопоставлен с `README.md`, `models.py`, `views.py`: автор, категория, изображения, лайки и `unique_together = ('user', 'project')` присутствуют; поиск, фильтрация, пагинация, проверка автора и login-required соответствуют описанию. Кейс явно ограничен фрагментами исходников: запуск полного пакета и production-деплой не заявлены. Схема данных подписана как схема, а не снимок действующего сайта.

NeuralBrief описан как проект из переданного владельцем профессионального контекста. Визуализация явно обозначена демонстрацией процесса, без реального запроса к AI и без выдуманных ссылки или метрик. Опыт и образование сопоставлены с проверенными родительским агентом фактами резюме; частные файлы резюме и контакты аудитор не публиковал.
